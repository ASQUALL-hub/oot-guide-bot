# Link's actions and movement

Every action Link can be in, and the physics of every way he moves, read from the decompiled game code.
This file is generated by `tools/write_actions_doc.py`. Bots should read `actions.json` (built by
`tools/build.py`): it has the same data plus animation lengths from your ROM and per-frame jump paths.

## Units

- **Speed** is the game's `speedXZ` value. Link actually moves **speed x 1.5 units per game frame**, and NTSC runs
  **20 game frames per second**. So speed 6.0 is 9 units/frame, or 180 units/second.
- **Each frame**, vertical speed gains gravity (never below -20), then Link moves by speed x 1.5.
- **Heights and distances** are in world units, the same as the collision and actor positions in `ootmap/`.

Speed formula: target = stick_term * 0.14 - 8 * s^2, clamped to [0, speed cap], where s = clamp(sin(floor pitch), 0, 0.6). stick_term at full stick (60): normal running ('curved') = 46.97, Z-targeted movement ('linear') = 48.0 (60 * 0.8). Speed moves toward the target by +2.0/-1.5 per frame (Kokiri boots).

## Uphill: which move is fastest

Speed is units per frame going straight uphill (adult, Kokiri boots). The sidehop chain counts each hop's airtime
plus the one landing frame before the next hop can start (Z held).

| Slope | Run | Backwalk | Sidehop chain (average) | Sidehop frames in air |
|---|---|---|---|---|
| 0° | 9 | 13.5 | 12.54 | 6 |
| 10° | 9 | 13.5 | 12.45 | 4 |
| 20° | 8.46 | 13.014 | 12.25 | 2 |
| 30° | 6.864 | 10.62 | 12.25 | 2 |
| 40° | 5.544 | 8.64 | 12.25 | 2 |

Backwalking keeps its 1.5x lead over running on every slope. Sidehops aren't slowed by the slope in the air, and
the next hop starts one frame after landing, so a sidehop chain stays near 12 units/frame uphill and passes
backwalking on steeper slopes. Very steep floors make Link slide, so check the slope before relying on it.

## Rules the movement follows

- **Brake skid when turning around while running:** turning the stick more than ~135 degrees (0x6000) while faster than 6.0 plays 'back_brake' (Link skids to a stop, then turns) (`z_player.c`).
- **Z with nothing to target locks facing ('parallel' mode):** pressing Z stores Link's current facing; movement then strafes/backwalks without turning. If Link is pushing a wall he snaps to face it (`z_player.c`).
- **Targeting jumps are blocked indoors:** sidehop/backflip/jumpslash via Z+A only work when the current room isn't type 'indoors' and the floor isn't type 7 / floor_effect 1 (`z_player.c`).
- **Indoor speed cap:** run speed limit drops to 5.0 in rooms marked indoors (`z_player_lib.c`).
- **Slopes slow walking, not targeting jumps:** walking/backwalking lose 8 x s^2 from their target speed (s = sin(slope), max 0.6); sidehop/backflip momentum is locked in the air (`z_player.c`).
- **Fall damage:** falls of 400-799 units: -8 health (half a heart); 800+: -16 (one heart). Floor types 6 and 9 never hurt (`z_player.c`).
- **Roll on landing skips fall damage:** landing from a fall of 81-799 units with the stick held forward (not carrying anything) starts a roll and skips the fall-damage check (`z_player.c`).
- **Hover Boots:** after leaving the ground Link stays airborne ~19 frames (vertical speed held at 1.0); run limit 5.5 (`z_player.c`).
- **Targeting jumps chain with ~1 frame of landing lag:** landing with Z held enters a targeting idle state that checks for the next Z+A jump every frame, even while the landing animation plays, so the next hop can start the frame after landing (`z_player.c`).
- **Momentum during targeting jumps:** while a sidehop/backflip is in the air (PLAYER_STATE2_19) the stick does not change speed or direction (`z_player.c`).

### Glitches (community knowledge, not checked against the code)

These are named in the randomizer's logic (`logic/helpers.json`, `--glitches` in `logic_eval.py`).

- **Infinite Sword Glitch (ISG)** (`glitch_isg`): keeps the sword's hitbox active indefinitely after an interrupted crouch stab.
- **Megaflip** (`glitch_megaflip`): backflip/sidehop boosted by explosion recoil while shielding, for a very long jump.
- **Hover (bomb hover)** (`glitch_hovering`): gaining height in midair with repeated explosion recoil.
- **Superslide** (`glitch_superslide`): keeps high speed from recoil while sliding/shielding.
- **Hookshot jump** (`glitch_hookshot_jump`): using the hookshot to gain height off certain surfaces.
- **Weirdshot** (`glitch_weirdshot`): hookshot/bow interaction that warps Link through geometry.
- **Ground jump** (`glitch_groundjump`): jumping from the ground using a held bomb/explosion.
- **Ocarina items (OI)** (`glitch_oi`): using an item from the ocarina/bottle menu state to get it early.
- **Equip swap** (`glitch_equip_swap`): using items with the other age's restrictions bypassed.
- **Recoil jump** (`adv_recoil_jump`): gaining distance from attack/shield recoil.
- **Damage boost** (`adv_damage_boost`): taking a hit to be knocked across a gap or onto a ledge.
- **Hover boots recoil** (`adv_hovers_recoil`): combining hover boots with recoil to cross large gaps.
